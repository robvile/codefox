# Changelog

## 0.5.2 — 2026-11-24

- **BUG FIX — toggling the Unity bridge off did nothing.** The toggle removed the bridge file and showed a "Bridge removed" toast, but the toggle stayed ON — because the Connections view re-rendered right after the removal and its auto-install put the bridge straight back. Root cause: the auto-install only checked "is the file missing" and had no memory of the user turning it off. Fixed with a persisted per-project `bridge_enabled_<id>` flag: toggle off sets it to 0 and removes the file, and every auto-install / auto-update path (startup, connect, switch, folder change, opening Connections) respects it, so off stays off. Toggle on sets it back to 1 and installs. The toggle's state is always re-read from disk after each operation.
- **BUG FIX — the CS1501 bridge error survived the v0.5.1 fix.** The fix was in the repo, but v0.5.1's auto-install only installed when the bridge file was MISSING — and a project that already had the broken bridge (installed by v0.5.0) kept it, so Unity kept reporting `error CS1501: No overload for method 'CreateAnimatorControllerAtPath' takes 2 arguments`. Fixed with bridge versioning: the bridge file now carries a `// CodeFoxBridge version: 0.5.2` marker and a `BridgeVersion` const, and CodeFox compares the installed version against the bundled one. On startup, connect, switch, or opening Settings → Connections, an out-of-date bridge is now overwritten automatically (toast: "Bridge updated to v0.5.2"). Upgrading from v0.5.0 to v0.5.2 fixes TD Pizza Racer's bridge on the next launch with no clicks — Unity may need a reimport/restart to clear the stale error. The v0.5.1 1-argument fix was verified still present in both the `.cs` file and the embedded copy.
- **Update plugin button is now disabled until it is needed.** It is greyed out with the tooltip "Bridge is up to date" while the installed bridge is current, and becomes clickable only when the installed bridge is older than the bundled one (or missing). Clicking it overwrites the bridge with the bundled copy, and it disables itself again afterwards. Its state is computed from the installed-vs-bundled version, not a guess.
- **The model MUST output the file, not just describe the fix.** A local model told to fix the CS1501 error replied that it "cannot modify files" — a prompt failure, not a capability failure, since the apply pipeline already works end-to-end (it created TestTMP.prefab). The system prompt now orders the model, in Agent mode: it MUST edit the project's files when asked to fix, change, create, or edit code, and describing the fix, explaining it, or saying it cannot modify files is a FAILURE. The app also enforces it: a refusal ("cannot modify files" and similar) triggers one automatic correction turn, and a reply with no file actions at all when the user asked for a change is treated as an incomplete turn and triggers one automatic follow-up demanding the file. One retry each at most; if the model still does not output the change, the loop stops and says so. The file parser also accepts ```` ```file:path ```` blocks as well as the documented `**File Path:**` + fenced block format (and a bare path line before a code block). **Diagnose error** now runs in Agent mode and, when the message is sent, the file named in the error is read and its surrounding lines attached to the prompt with an instruction to output the fixed file. A local model can still fail to comply — this is prompt engineering plus enforcement, not a guarantee. A short hint under the composer in Agent mode says the mode writes code to the project, with a snapshot taken first and revert available.
- **Version.** package.json is now 0.5.2; the sidebar footer reads "CodeFox 0.5.2 — Local · No account needed".

## 0.5.1 — 2026-11-24

- **New Unity asset files auto-apply.** When the assistant creates a NEW Unity-native file — a prefab, scene, material, animation, controller, or similar (a file that contains no code) — CodeFox now writes it straight away after taking a snapshot, without asking you to click Apply. A simple request like "create a prefab called TestTMP with a TextMeshPro object" finishes in one turn. New setting `auto_apply_unity_assets` (default on, Settings → Advanced → Approvals). Code files (.cs, .shader, .js, .ts) and edits to files that already exist still show the Apply bar first, unless auto-accept is on. If a change set is mixed — any code file, or any edit to an existing file — the whole set asks first; auto-apply never writes half a set. In the Agent loop an auto-applied write counts as an executed action, so the loop keeps going without pausing. The asset list lives in one place (`unity-assets.js`, shared with the renderer through preload) and is unit-tested in the smoke test.
- **Revert is always available after any apply — and Keep is explicit.** The revert bar now appears after EVERY apply (manual Apply click, auto-accept, or the new auto-apply) and stays until you click Revert or Keep: it never auto-dismisses on a timer, and a new chat message does not replace it. Its text now says what each button does: Revert restores the files as they were before the change (new files are deleted); Keep discards the snapshot, so the change can no longer be reverted. **Keep changes is now a deliberate click that actually discards the snapshot** (new `db:deleteSnapshot` IPC) — before this, Keep only hid the bar and the snapshot lingered in the sidebar. Nothing discards a snapshot automatically: not closing the app, not starting a new conversation. Reverting also discards the spent snapshot so it cannot be reverted twice. The sidebar already lists the last 5 snapshots, most recent first, each with its own ↩ revert button — that still works, and the list now refreshes immediately after an apply.
- **BUG FIX — Unity bridge would not compile (CS1501).** The auto-installed bridge called `AnimatorController.CreateAnimatorControllerAtPath(assetPath, 1)`, but that method only has a 1-argument overload — `CreateAnimatorControllerAtPath(string path)` — in every Unity version, so Unity reported `error CS1501: No overload for method 'CreateAnimatorControllerAtPath' takes 2 arguments`. The second argument was a layer count; the 1-argument call already creates the controller with a single default "Base Layer", so the intent is preserved. Fixed to the 1-argument call in `unity-companion/CodeFoxBridge.cs` and the embedded copy was regenerated with `node scripts/embed-bridge.js` (it now matches the fixed file). The rest of the bridge was audited for the same problem — every other API it uses (`AssetDatabase.FindAssets` / `GUIDToAssetPath` / `LoadAssetAtPath` / `SaveAssets` / `Refresh`, `AddState` / `AddTransition` / `AddCondition`, `AddParameter`, `Undo.RegisterCreatedObjectUndo`, `EditorApplication.ExecuteMenuItem`, `EditorUtility.RevealInFinder`, `JsonUtility.FromJson`) has existed since Unity 5.x/2017, so no other calls needed changing. Not compiled inside a real Unity Editor here — confirm the error is gone after reinstalling v0.5.1 and letting the bridge auto-install.
- **Version.** package.json is now 0.5.1; the sidebar footer reads "CodeFox 0.5.1 — Local · No account needed".

## 0.5.0 — 2026-11-24

- **Agent mode is now a real loop (Agent mode only).** After each reply, CodeFox parses the reply for actions — file changes, ```powershell / ```pwsh / ```shell blocks, ```upm-install / ```upm-remove blocks — runs the allowed ones, asks about the rest, appends every result as a tool-result message in the thread, and calls the model again with the extended history, so it can build, see the error, fix it, and rebuild without another prompt. Ask and Plan modes are unchanged: one reply, then the bars, no looping. New `runAgentTurn` / `streamOneTurn` flow in app.js; the old one-shot `onDone` handler is gone.
- **Max rounds + Stop.** New `agent_max_rounds` setting (default 5, range 1–10, in Settings → Advanced). The loop stops when a reply has no actions, when the max is hit ("Stopped after N tool rounds — the task may need more steps. Ask me to continue if you want."), or when the user clicks the new **Stop** button under the reply ("Stopped by user."). The max is a hard cap. A status line under the reply shows the current round and the last action ("Working… round 2/5 — ran `dotnet build`").
- **Approval pauses that resume.** When an action needs approval, the loop pauses on the existing bar (apply bar / shell bar / new package bar) instead of skipping or running it. Approving runs the action, appends its tool result, and resumes the loop; dismissing appends a "User declined" note and resumes, so the model can try a different approach. The system prompt (Agent mode only) now tells the model it can use ```powershell and ```upm-install blocks, that output comes back as tool results, and that it should stop and summarise when done.
- **Unity Package Manager (manifest-based).** New IPCs `unity:listPackages`, `unity:addPackage`, `unity:removePackage` in main.js (backed by the plain-Node helper `upm-manifest.js`, unit-tested in the smoke test). CodeFox edits `Packages/manifest.json` directly — it does not claim to use Unity's Package Manager API — backs it up first to `Packages/manifest.json.codefox-bak`, writes it back with 2-space indent, and triggers a Unity refresh via the existing sentinel. The project scan now includes installed packages (requested + locked versions) so the model knows what is already installed, and Settings → Connections (and the Connections view) lists them under the Unity row with a per-package Remove button (confirm click).
- **Package installs always ask.** There is no auto-run path for packages — not in Auto Mode, not with auto-accept on. The new package bar (`package-bar`) shows the name + version, with an editable version field when the model gave none (Install stays disabled until a valid version is typed — a version is never guessed) and an editable name field for a bare git URL. ```upm-remove blocks work the same way with a Remove button. The smoke test asserts the install call is only reachable from the approval-bar handler.
- **Safety, extended and visible.** Dangerous commands now also include `rmdir /s`, `rd /s`, and `Remove-Item -Force -Recurse` — they never auto-run in any mode. Settings → Advanced has a new "What runs automatically, what always asks" summary and the max-rounds setting. A loop never runs a command while the shell is off, and never installs a package while no project folder is set.
- **BUG FIX — Unity bridge install failed in the installed app.** Root cause, confirmed: `unity:installBridge` read the bridge from `unity-companion/CodeFoxBridge.cs` under the app folder, but electron-builder's `build.files` list never included `unity-companion/`, so the installed app had no such file and every install (Update plugin, enable toggle) failed with a "Companion script not found in the app install" warning. Fixed in three layers: (1) packaging — `unity-companion/**/*` (plus the new `upm-manifest.js`, `unity-bridge.js`, `unity-bridge-source.js`) is now in `build.files`, so the file is in the installed app; (2) embedded fallback — `scripts/embed-bridge.js` (run before every build) generates `unity-bridge-source.js` from the `.cs` file, and `unity-bridge.js` installs from the bundled file first and the embedded copy when it is missing, so the install can never fail for a missing source file — the old warning is gone entirely; (3) auto-install on connect — the bridge installs automatically when a project is created, switched to, or given a new folder, when the app starts with a project already set, and when Settings → Connections is opened on a project without one; a real failure (e.g. folder not writable) is shown as the status there. The audit found no other runtime file with the same packaging gap: the only other files the installed app reads from its own folder are `preload.js` and `build/icon.png`, both already in `build.files`.
- **Version.** package.json is now 0.5.0; the sidebar footer reads "CodeFox 0.5.0 — Local · No account needed".

## 0.4.0 — 2026-11-24

- **Settings is now a full window, not a popup.** Clicking Settings in the sidebar or the top bar opens a centre view (mode `settings`) with its own sub-nav — Model, Connections, MCPs, Rules, Advanced — while the left sidebar stays visible. The old `openSettings()` modal is gone; the small New item / New Project / Rename prompts still use the modal overlay. There are deliberately no account, subscription, or multi-user sections: CodeFox is a single-user local app.
- **Model section** — the old popup's contents moved into the window: provider (LM Studio default / Ollama), LM Studio URL with Verify connection / Refresh models and a live status line, model picker from the live server list, optional API key, temperature, max tokens, project path + context, Unity Editor exe path + Browse. Saving still keeps the current thread (no reload).
- **Connections section** — "Your Connections" with Unity / Folders filter chips, "+ Add Unity project" and "+ Add folder" buttons, one row per connection. The Unity row shows the active project's name and path, a live Connected/Not connected status derived from whether `Assets/Editor/CodeFoxBridge.cs` exists, an "Update plugin" button that re-installs the bridge, an enable toggle (off removes the bridge), and a ⋯ menu with Disconnect. New `unity:removeBridge` IPC in main.js (deletes the bridge file and the refresh sentinel). Bridge status is also reflected on Home's Unity connection card.
- **MCPs section** — configure local MCP servers (name, command, args, `KEY=value` env lines, enabled toggle), stored in the new `mcp_servers` setting. Honest scope: MCP servers are configured here for now; the assistant does not call MCP tools yet, and the UI, README, and changelog all say so. No cloud marketplace, no fake one-click installs.
- **Rules section** — per-ruleset enabled toggles (new `enabled` column on `rulesets`, default 1) and priorities (new `priority` column, higher = sent first). A prompt budget (`rules_char_budget`, default 4000, 1000–12000) caps how many characters of rules go with each message — whole rulesets only, never cut mid-way — and the section shows what was included in the last message and what was left out. **Condense rules** asks the model for a sub-500-character version keeping every hard constraint, stored in `condensed_rules`; with **Use condensed rules when over budget** on, that version is sent instead of dropping rules. If the model can't be reached, condensing shows the real error and changes nothing.
- **Advanced section** — Shell Tool toggle (`shell_enabled`, default OFF; when off nothing can run and the rest of the section is greyed out), Auto Mode (`shell_auto_mode`, default OFF), auto-accept project changes (`auto_accept_changes`, default OFF — still snapshots first, revert bar always shown), an editable auto-approved command list (`shell_auto_approve`, defaults `git status`, `git diff`, `npm test`, `npm run test`, `dotnet build`, `dotnet test`), and an editable Excluded File Types list (`excluded_file_types`) that project scans and file search actually skip. New `shell:run` IPC runs PowerShell on Windows (`pwsh` fallback) or `sh -c` elsewhere, 60-second timeout, output truncated to 8000 chars per stream, refused outright while the shell is off. Assistant replies' ```powershell / ```pwsh / ```shell blocks auto-run only when the shell is on, Auto Mode is on, the first line matches an auto-approved prefix, and the command is not dangerous — `rm`, `del`, `Remove-Item`, `format`, `rm -rf`, and `Remove-Item -Recurse` always require a Run click. Otherwise a Run / Dismiss bar appears. A manual "Run a command" box in Advanced tests the shell directly. Editor Integration honestly states the Unity bridge is the editor integration, with a link to Connections — no fake toggles.
- **App icon** — the app icon is now the kitsune nine-tails mark from Home, rendered to `build/icon.png` (512×512) and `build/icon.ico` (16/32/48/256), and wired into the build config and the app window. The binaries are stored in the repo as base64 text and regenerated by `scripts/prepare-icons.js` before every build.
- **Version.** package.json is now 0.4.0; the sidebar footer reads "CodeFox 0.4.0 — Local · No account needed".

## 0.3.2 — 2026-11-24

- **Unreal UI elements removed.** The "Add Unreal Project" card is gone from Home, along with its handler and stored-path state. CodeFox is Unity-focused and cannot program in Unreal yet, so the UI no longer implies otherwise. (The README says so plainly.)
- **New mark: a nine-tailed fox.** The ghost-like icon on Home is gone — it looked too close to another app's mascot. In its place is an original kitsune mark: a fox head with nine tails fanning out behind it, drawn as inline SVG in CodeFox's own colours.

## 0.3.1 — 2026-11-24

- **One installer, always the same name.** The Windows installer is now always `dist/CodeFox-Setup.exe` — no version number in the filename, so rebuilding overwrites the previous one instead of piling up `CodeFox Setup 0.2.0.exe`, `CodeFox Setup 0.3.0.exe`, and so on. Every build script (`build`, `build:win`, `build:mac`, `build:linux`) cleans `dist/` first via `scripts/clean-dist.js`. Delete any old versioned installers in `dist/` once; new builds will never create another one.

- **Home view.** CodeFox now opens on Home instead of jumping straight into a chat: a project banner (CSS-only pattern, "Local" badge, Edit button), Your Connections cards, a Discover Skills grid, Recent References, and a "What do you want to build?" panel with starter pills (Debug an issue / Build a tool / Write a script), a composer, the Ask/Plan/Agent dropdown, the active model name, and a status dot. The top bar has a centred title, a sidebar toggle, and new-conversation / focus / panel buttons; the LM Studio status dot lives there.

Project selector dropdown with switching, Project Settings (rename / change folder), and New Project. Deleting a project deletes its conversations and references with it; the last project cannot be deleted. New IPC: `project:list`, `project:create`, `project:switch`, `project:update`, `project:delete`. No accounts, no invites, no team plan.
- **Conversations and References.** "Threads" is now "Conversations" and "Pages" is now "References" throughout the UI. The References list shows pages and plans together, labelled "Reference" and "Plan".

Manage Skills lists all six with Install/Uninstall toggles.
- **Working together (planned, not in this release).** Simultaneous multi-user editing is not included. The per-project data model is the foundation; a future sync layer would need a shared project store, presence, and conflict handling for apply/revert.
- **Version.** package.json is now 0.3.0; the sidebar footer reads "CodeFox 0.3.0 — Local · No account needed".

## 0.2.0 — 2026-11-24

- **LM Studio is now the default backend.** OpenAI-compatible local API (`/v1/models`, `/v1/chat/completions` with SSE streaming). Ollama keeps working as the alternative backend for existing users.
- **New Settings menu.** Pick the provider (LM Studio / Ollama), verify the LM Studio connection with a real status line, and select a model from the live list returned by the server instead of typing a name. Also: optional API key, temperature, max tokens, and the Unity Editor exe path used by Run tests. Settings save without losing the current thread (no reload).
- **Ask / Plan / Agent modes.** Ask answers only, Plan drafts steps and file lists without writing code, Agent works step by step and outputs complete code, one file per fenced block.
- **Project scan.** Scans the Unity project (version from `ProjectVersion.txt`, packages from `Packages/manifest.json`, scenes and prefabs with GameObject names, script list) and includes a truncated summary in every prompt.
- **Tools row.** Scan project, Diagnose error, Generate tests, Animator, UI, Run tests, Build check.
- **Test loop.** Generate NUnit EditMode tests, run them in Unity batch mode (10-minute timeout, XML results parsed for pass/fail/skip), and a `dotnet build` check. Both report honestly when they cannot run — they never fake a pass.
- **Error diagnosis** from a pasted Unity console error or log.
- **Animator and UI generation** prompts, plus a Unity bridge that executes `createAnimatorController` and `createUICanvas` commands from `Assets/.codefox-command.json` and reports back in `Assets/.codefox-result.json`.
- **Diff preview.** A Review diff button in the apply bar shows a line-based diff (added / removed / unchanged) per file before applying.
- **Safer apply/revert.** `fs:writeFile` creates parent directories; new files are recorded in the snapshot with a sentinel so revert deletes them (and their `.meta`); `fs:moveFile` moves a file together with its `.meta` sibling, preserving Unity GUIDs.
- **New IPC surface.** `llm:status`, `llm:listModels`, `llm:verify` (connection + model list, plus a tiny chat probe only when a model is selected), unified `llm:chat` (legacy `ollama:stream-chunk` / `ollama:stream-done` events still emitted), `project:scan`, `unity:runTests`, `unity:buildCheck`, `fs:pickExe`.
- README rewritten for LM Studio first, with honest model-size / VRAM guidance and a "What local models can't do as well as cloud models" section.
